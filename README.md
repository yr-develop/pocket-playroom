# POCKET PLAYROOM

昔の携帯ゲーム機くらいの手触りを目指した、11本のブラウザゲームを収録するロビーです。

## 設計方針

- `index.html` を常にロビーの入口にする
- 各ゲームは `games/<game-id>/` にHTML・CSS・JavaScriptを閉じ込める
- 色、筐体、画面、基本タイポグラフィは `assets/css/base.css` で共有する
- ロビーのゲーム一覧は `assets/js/games.js` のカタログから生成する
- 十字キー・A/B・キーボード入力は `assets/js/controls.js` の `pocket-input` イベントへ統一する
- 長押しが必要なアクション向けに `pocket-input-start` / `pocket-input-end` も共通化し、アクションゲームでは画面内十字キーを押している間の連続移動に使う
- 共通配置は「十字キー・SELECT・START・B/A」とし、中央の補助ボタンはSELECT・STARTの2つだけにする
- SELECT・STARTは配置を固定し、必要に応じてHOLD・MENUなどゲーム内での役割を表示する
- 効果音は `assets/js/soundboard.js` の名前付きサウンドプールへ集約し、ゲーム側は `PocketSound.play()` で参照する
- サウンド設定はロビーと各ゲームで共有し、ブラウザのローカルストレージへ保存する
- ゲームデータは外部サービスに依存させず、静的ホスティングで動作させる
- 操作可能要素は48px前後を確保し、マウス・タッチ・キーボードを同じ優先度で扱う
- `100svh`、セーフエリア、縦横レイアウトを考慮し、320px幅からデスクトップまで対応する
- 画面サイズにかかわらず430×800の縦型筐体を基準とし、必要な場合だけ全体を等倍縮小して余白を背景として残す
- 画面の演出を減らすOS設定（`prefers-reduced-motion`）を尊重する

## ゲームを追加する

1. `games/<game-id>/index.html` を作る
2. 必要ならゲーム専用のCSS・JavaScriptを同じフォルダへ置く
3. `assets/js/games.js` にタイトル、説明、リンクなどを1件追加する
4. `node scripts/build.mjs` を実行して配布用の `dist/` を更新する

ロビーのHTMLを編集せずにゲームを追加できます。

## 共通操作とサウンド

- 十字キー: 選択・移動（キーボードの矢印キーにも対応）
- Aボタン: 決定・主要操作（Enter、Zにも対応）
- Bボタン: 戻る・副操作（Space、Escape、Xにも対応）
- SELECT・START: ゲームごとの補助操作（キーボードのQ・Sにも対応）
- 進行中の内容を破棄するNEW操作: 対応ボタンを3秒長押しし、画面内カウントダウン完了後に実行
- 効果音を追加するときはゲーム内で発振器を直接作らず、`soundboard.js` の `SOUNDS` へ短いパターンを登録する

## 収録ゲーム

- ひとりババ抜き: CPUの手札は初回とCPUの各ターン終了時に、演出中の見えないタイミングでデータ配列ごと再シャッフルする
- スライドパズル: 3×3・4×4・5×5、タップと十字キー操作、手数と0.1秒単位のタイマーに対応する
- 絵合わせポーカー: CPUと5枚の独自記号カードで対戦するドローポーカー。変更対象、CPU交換、SHOW DOWN、勝敗、BET、配当を管理する
- テトリス: 7バッグ方式、SRS回転、NEXT 3個、HOLD、ゴースト、レベル・ライン・スコア、ポーズメニューに対応する
- 本格ポーカー: 52枚デッキのCPU戦。カード交換後にBET調整、SHOW DOWN、FOLDを行い、最低ベットは3ラウンドごとに上昇する
- ポケットインベーダー: 編隊移動、敵弾、破壊可能な防御シールド、残機、スコア、ハイスコア、ウェーブ進行に対応する
- ブロック崩し: 反射角度の変化、残機、スコア、ハイスコア、ステージ進行に対応する
- マインスイーパー: 初手安全、空白の連鎖展開、フラグ、タイマー、9×9と12×12、NEWの3秒長押し保護に対応する
- ポケットスネーク: 壁衝突と画面ループの2モード、加速、レベル、スコア、ハイスコアに対応する
- ポケットランナー: 自動横スクロール、1ボタンジャンプ、速度上昇、障害物、スコア、ハイスコアに対応する
- ビートパレード: 矢印・A/Bの6レーン、コンボ、スコア、BAD・OK・GOOD・NICE!のタイミング評価に対応する

テトリスの基本ルールは[Tetris公式のゲーム説明](https://play.tetris.com/about)、回転中心とウォールキックの実装値は現行Guideline標準を整理した[TetrisWikiのSRS資料](https://tetris.wiki/SRS)を参照しています。

## ローカルで確認する

ルートを任意の静的サーバーで配信してください。専用のBAT・常駐サーバーツールは使用しません。

例:

```sh
python -m http.server 4173
```

その後、`http://localhost:4173/` を開きます。直接 `index.html` を開いても基本機能は動作します。

## 配布用ファイルを作る

```sh
node scripts/build.mjs
```

`dist/` に静的ファイル一式が生成されます。

## GitHubでの管理

- リポジトリは非公開を基本とし、明示的に招待した共同編集者以外へソースを公開しない
- `main` を正本とし、公開前に `node scripts/build.mjs` とJavaScript構文確認を行う
- GitHub Pagesはサイト自体がインターネット公開になるため、公開範囲を了承するまで有効化しない
- パスワード、トークン、個人情報などの秘密情報はHTML・JavaScript・コミットへ含めない
